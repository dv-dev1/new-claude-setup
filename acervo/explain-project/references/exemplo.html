Os dois projetos

LLM na borda, código determinístico no core

O modelo só faz o que é probabilístico: interpretar texto. Tudo que tem consequência (preço, autorização, estado) sai de código puro com teste. A diferença está no tipo de sistema: a Empório é um agente conversacional, em que o LLM conduz a conversa, e a Vitalis é um workflow assíncrono, em que o LLM é um detalhe opcional.

O esqueleto que se repete
  1. entradaChega texto livre

    Empório: pergunta do cliente. Vitalis: nome do exame escrito pelo médico.

  2. LLMInterpreta e escolhe de uma lista fechada

    Empório: qual das 5 tools chamar. Vitalis: qual código do catálogo sugerir.

  3. códigoValida o que o LLM devolveu

    Tipo do argumento, nome da tool, código dentro do catálogo.

  4. códigoFunção pura decide

    Parcelas e desconto PIX; periodicidade e necessidade de autorização.

  5. SQLiteGrava o estado

    Histórico da conversa; solicitação, exames, eventos e queue.

  6. códigoResolveu?
    simresposta ou estado final
    nãopessoa assume, com a tarefa escrita

Agent loop com tool calling

tool calling · function calling · agent loopO modelo só pede a função; o seu código executa.›

O LLM nunca executa nada. Ele devolve um JSON com o nome da função e os argumentos (finish_reason: "tool_calls"). O código roda a função, devolve o resultado como mensagem role: "tool" e chama o modelo de novo. O "agente" é esse for.

def max_installments(amount: float) -> int:
    best = 1
    for ceiling, floor in INSTALLMENT_FLOORS:
        for count in range(best + 1, ceiling + 1):
            if amount / count >= floor:
                best = count
    return best
